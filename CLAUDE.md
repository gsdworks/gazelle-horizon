## Build discipline
- Never edit Horizon core files; all custom files prefixed `gazelle-`.
- `gazelle-pull` before ANY editor session or any diagnostic reading editor-owned JSON (index.json). Pull-clobber is a read-accuracy rule, not just write-safety.
- "In the repo ≠ committed" — commit in the same session. And committed ≠ pushed — push too.
- A Matrixify green "OK" is NOT a verified write — confirm against a store export.
- A finding needs a victim — name who's harmed and how, or it's a curiosity, not a finding.
- Verify against source before flagging; confirm a column is populated before reading its absence as a finding.

## Session-end update — run when Grant types `/update-context` (follow EXACTLY, every time)
1. **Read the current STATUS.md first** (never regenerate from memory — that silently drops open loops).
2. **Append** newly-completed/discovered items to the bottom of DONE.md, dated `YYYY-MM-DD`. Full detail is welcome and encouraged — findings, email facts, reasoning, decisions. Append only; never edit existing DONE lines.
3. **Rewrite STATUS.md whole:** open loops (owner — item — next action — since), blocked-on, next actions. Delete anything now done (it's in DONE.md). Keep it under ~100 lines.
4. Only if an area changed materially, update its docs/ file (or note it for the monolith carve).
5. Run `./build-context.sh` to regenerate PROJECT-CONTEXT.md.
6. Commit all changed files in ONE commit (`context: <date> — <headline>`) and **push**. `git log` is the history — do not hand-write dated changelogs anywhere.
7. Finish by telling Grant, verbatim: **"Now drag PROJECT-CONTEXT.md into project knowledge (replace the old one)."**

If Grant pasted a DIGEST with the command, fold it into steps 2–3 in full — do not compress it.

## DIGEST PROTOCOL — for Claude in claude.ai / Desktop chats (this section travels via PROJECT-CONTEXT.md)
When Grant says **"digest please"** (or "digest", "give me the digest") at the end of a chat, produce EXACTLY this, in one copyable code block:

1. A line: `/update-context DIGEST (<today's date>):`
2. **DONE entries** — one dated paragraph per completed/discovered item from THIS chat, in full detail: what was found, why, what was decided, key facts from emails, exact strings/numbers that matter. Write it so someone reading DONE.md in six months needs no other source.
3. **STATUS changes** — lines starting `STATUS:` for each open-loop change: new loops (owner — item — next action), loops to close, loops that advanced.
4. Nothing else — no preamble after the block, so Grant can copy-paste the whole thing straight into Claude Code.

Rules: never invent items not established in the chat; mark anything unverified as UNCONFIRMED; include client-email facts verbatim where they're load-bearing. If the chat produced nothing worth logging, say so instead of manufacturing a digest.
